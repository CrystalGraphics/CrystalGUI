# CrystalGUI — load-bearing invariants

**The things that are invisible from any single class and expensive to rediscover.** This was a section
of `AGENTS.md` and outgrew it: 542 rows, 560 lines, a quarter of the file that is loaded at the start of
every session. It is here so that reading it is a choice.

## What earns a row

A row earns its place by describing something that is **TRUE NOW** and able to bite somebody. A rule the
engine no longer has is deleted; a rule whose mechanism was renamed is rewritten, never left naming a
class that is gone.

The one deliberate exception is a row recording a repair that was **tried and did not work** — those are
marked, and they are here because the next person will otherwise try it again.

**A rule stated twice drifts.** If the frame lifecycle, the Taffy defaults table or a stack section in
`AGENTS.md` already says it, this file does not repeat it — the terse copy is the one that goes stale,
because nobody re-reads it when the mechanism moves.

> **244 rows were cut when this file was split out**, and the discriminator was tense rather than
> subject: a row that states a constraint stayed, a row that narrates one fixed bug in one class went.
> They are not lost — `git show <the split commit>^:AGENTS.md` has all 542 — but they were history
> rather than knowledge, and history has somewhere better to live.

## Threading, and what may run on the frame thread

| Invariant | Consequence if violated |
|---|---|
| **THE FRAME THREAD OWNS THE TREE, PER **TREE** AND NOT PER PROCESS** — `UiThread.require(what, treeOwner)`, asked of the element's attached window | `UiThread` recorded which thread ran frames and **asserted nothing**, so the rule lived only in a javadoc — and had already been paid for once: a script thread emitted a signal, a listener called `setEnabled`, that reached `invalidateStyleMatch()`, and the cascade's dirty-match `HashSet` was mutated while the frame thread copied it (`ArrayIndexOutOfBoundsException: Index 358 out of bounds for length 358` out of `HashMap.keysToArray`, thrown in `advanceFrame` with nothing about the Run panel in the trace). A trace at the WRITE names the culprit; a crash a frame later names the victim. **Per-tree is what makes it usable rather than merely correct**: a tree nothing has painted has no owner, so every headless test, dedicated server and background build is free, while a tree that IS being painted refuses everyone but its painter. A process-wide owner fails a suite wholesale — JUnit's `timeout` runs only the method BODY on a fresh thread while `@Before` runs on the runner's, so one logical test spans two OS threads and the refusal reads *"must happen on (Time-limited test), not on Time-limited test"*, the same name twice, which looks like the check being broken |
| **THE FRAME THREAD OWNS THE TREE — what may run on it is decided by OWNERSHIP, not by cost** | `UINode`, `ElementStyle`, the live Taffy tree, the box tree's composed matrices and `Input`'s hover/focus/capture are mutable, cross-referential and read during paint, and none has a safe concurrent reader. So everything that touches the tree — cascade, layout, hit-testing, input dispatch, paint, and every listener that reaches an element — **must** run there; moving it off means locking the tree (which serialises anyway and deadlocks against paint) or snapshotting it (dearer than the work saved, for thousands of nodes). Every reference draws the same line: Chrome's main thread runs script, style, layout and paint recording while only compositing and raster leave it, and AppKit, GTK, Swing's EDT, the JavaFX application thread and Android's UI thread all agree. **The rule that follows is the useful half: anything that is a pure function of a SNAPSHOT must not run there** — I/O, opening an archive, compiling, decompiling, indexing, probing a classpath. Those go to `JobScheduler`, whose `onDone` hands the answer back on the frame thread during `drain()`. `UiThread.markCurrent()` is called from `UIDocument.frame`, so "the frame thread" is whatever actually draws — a window, the harness, or a test stepping frames |
| **...and the leak is never at the CALL SITE, so a guard beats an audit** | Two calls cost this application its frame rate and both looked free from every caller. `ContentProvider.symbolOf(Resource)` reads exactly like a property getter and ran a **761ms** compile the first time it was asked about a class — from a tab presentation the dock re-reads on every strip rebuild and from a tree row bind. `HostClasspath.detect()` reads like a getter and opened **every jar on the classpath**: 3-5ms over 23 entries against an 8.3ms budget at 120Hz, and its own javadoc said those archive opens were "paid once per process" while with no cache they were paid once per CALL. Nobody wrote a bad call site, so auditing call sites would have found neither. `UiBudget` times every provider call at the `Workspace.providerFor` door — the one they all go through — and names any that cost a frame. **Always on**, because a guard behind a flag catches nothing, and it costs one volatile read off the frame thread. `symbolOf` may now answer "not yet" and announce through `ContentProvider.onDidResolveSymbol`, which the workbench coalesces into the same flag a project file's late declaration already sets. **And a guard is only as good as its wiring**: this one is a static nothing forces a caller to use, so deleting the registry that held the timing wrapper unhooked it while every test stayed green and every javadoc still described it. `ProviderCallsAreBudgetedTest` asserts through the door rather than through `UiBudget`, so moving the door fails the test instead of silently unwiring the guard |
| **A signal emitted by a WORKER thread carries that thread into every listener — and the engine's first touch is usually invisible** | `RunSessions` is written by the thread whose script just changed state and emits inline, so `onDidChange` handlers run on a script thread by construction. `ScriptWorkbench` pushed the Stop button's enablement from one; `setEnabled` ends in `invalidateStyleMatch()`, which added to `StyleEngine`'s dirty-match **HashSet** while the UI thread was copying it — `ArrayIndexOutOfBoundsException: Index 358 out of bounds for length 358` from `HashMap.keysToArray`, thrown in `advanceFrame` with **nothing about the Run panel anywhere in the trace**. Nothing at the call site looks threaded, which is the whole difficulty: one innocuous setter reaches the cascade. **The fix is PULL, not a lock and not a hop** — `RunPanel.refreshActions` already recomputed the same value every frame from the same object, and a per-frame reader cannot race the frame it reads in. Where a push is genuinely required, hop through `JobScheduler`, whose `onDone` is documented to run on the UI thread during `drain()` — `RunIndicators` is the reference. A `ConcurrentLinkedQueue` drained in the frame is the other safe shape, which is exactly why `RunConsole`'s transcript is one |

## The node tree, the box tree and coordinates

| Invariant | Consequence if violated |
|---|---|
| **A raise is a `z-index` assignment and NEVER a child-list move** — `Desktop.raise` writes IMPORTANT-origin z; `sortedChildren` already keeps paint order and hit-testing agreeing | `remove`/`append` is `unregisterElement`/`registerElement` over the whole frame subtree — session state captured and re-applied, modal/popover/close-watcher stacks popped, every Taffy node destroyed and rebuilt — and a raise happens **on a click**, which is exactly when a widget must never rebuild the elements it is being clicked on. It would work, and the window would slowly lose state nobody could attribute to clicking it |
| **Adding a child from inside `onWindowChanged` or a refresh inserts a Taffy node into a parent whose children are still being registered** | `Index (is 1) should be < child_count (0)`, the crash `UINode.taffyChildIndex` is named after, reached from a new direction: `Taskbar.onWindowChanged` calls `refresh()`, so building anything lazily from inside entry construction runs during the taskbar's own attach. Build a widget's own children in its CONSTRUCTOR — all of them, before attach — and resolve whatever they need lazily instead. It is the second time this session an existing documented hazard was met by creating a new instance of the case it covers |
| **A LEAF WITH A `MeasureFunc` WAS MEASURED AGAINST ITS CONTAINER'S MAIN SIZE, NOT ITS OWN, UNDER `flex-wrap: wrap`** — Taffy's `determineHypotheticalCrossSize` read `isWrap ? NaN : targetSize`, and the branch is now **deleted** in the vendored fork | The leaf's **width stayed correct** and only its height was short, so the symptom is clipped text rather than a box that looks wrong. Measured on a 200px row of two `flex-grow: 1` text leaves: `nowrap` told the measure function **100** and `wrap` told it **200**, so the leaf reported a height for a width it was never given. `UIText` avoids the whole path with a post-layout recompute and its javadoc named this defect as the reason, ending *"not something fixable without forking a third-party Maven dependency"* — the fork is now `taffy/`. **The branch was not protecting the aspect-ratio case it was written for, it was destroying it**: four of five AR shapes in a wrapping row came out **zero-high**, where `nowrap` gave the right answer. Three independent things agree on deletion — CSS Flexbox §9.4 step 7 says to measure with the **used** main size, upstream Rust Taffy passes it unconditionally, and after deleting, every single-line shape matches `nowrap` while the genuinely two-line one is unchanged. `taffy/MODIFICATIONS.md` #1; covered at both levels (`TaffyWrapMeasureTest`, `MeasureFuncUnderFlexWrapTest`), and the counter-assertion matters because every other assertion is "wrap must equal nowrap", which a fix that stopped wrapping would satisfy |
| **THE MOD JAR IS HALF FASTUTIL, FOR SEVEN TYPES** — 12,808 relocated entries, ~22MB of a 48MB jar | Taffy's own dependency, for `IntList`/`IntArrayList`, `FloatList`/`FloatArrayList`, `Int2FloatMap`/`Int2FloatOpenHashMap` and `Long2ObjectOpenHashMap`. Replacing them with primitive collections of our own is a large and cheap win now the port is vendored, and deliberately **not** done inside a spike: swapping a hash map implementation inside a layout engine wants its own tests (`Int2FloatOpenHashMap`'s default return value is the sort of thing that is silent when wrong). Recorded in `gradle.properties` and `taffy/MODIFICATIONS.md` so it is not rediscovered |
| **A PROJECT DEPENDENCY PUBLISHES SEVERAL VARIANTS WHERE A MAVEN ARTIFACT PUBLISHES ONE** | The moment Taffy stopped being `dev.vfyjxf:taffy` and became a module, `mc1710:shadowJar` failed before it started — *"we cannot choose between the following variants of project :taffy"* — because GTNH's `shadowImplementation` carries RetroFuturaGradle's obfuscation attributes and could not pick between `classes` and `resources`. Naming `LibraryElements.JAR` is the fix, and it then needs an **explicit `dependsOn(":taffy:jar")`**: Gradle cannot infer the producing task through an attribute override, and says so rather than racing. The RFG attributes listed in that error are unmatched on every variant equally and are not what the resolver is stuck on |
| **...and it must be RELOCATED when the host already ships an older copy** | LaunchWrapper carries `asm-debug-all-5.0.3` and `org.objectweb.asm.` is in `LaunchClassLoader`'s parent-first exclusion list, so an unrelocated bundle always loses to 5.0.3 whatever the jar order — and 5.0.3 predates `ClassRemapper` (it is `RemappingClassAdapter` there), which is precisely the class the `NoClassDefFoundError` named. Relocation is what lets both exist. **The JOML rule still governs which may be relocated**: no ASM type appears in a signature another jar defines, `core/` never references it and CrystalGraphics does not ship it, so every reference lives in the jar the relocation rewrites. Taffy and ASM pass that test; JOML does not |
| JOML + Taffy must stay on the headless classpath | Field descriptors resolve at class load; `UINode`/`ElementStyle` have fields of those types |
| A drag's own delta is the truth at drag end, **never a re-read of the layout** | `worldBoundsOf()` reports the last *computed* layout, and the final `moveNode` of a drag writes insets Taffy has not resolved yet — so asking at drag end returns the position before the last move, and a short drag records a delta of zero and no undo step at all |
| A widget must never rebuild the elements it is being clicked or dragged on — update them in place | The mouse-down handler detaches the element under the cursor, and a drag's source detaches on its first update, so `screenToLocal` goes stale and every later frame feeds the drag garbage. The table header froze exactly this way: sort once and no header could be clicked or resized again |
| Resize is clamped to the containing block for out-of-flow elements only — and it is `resizeContainingBlock()`, not `getParent()` | Clamp only the move and a box parked at the corner can be *grown* out through it; clamp against the DOM parent and a promoted dialog stops short with window to spare |
| **A search marks the matched CHARACTERS, never the whole row** | `SearchMatch` has carried `ranges` all along and nothing asked for them. IntelliJ bands the query span in amber, VS Code recolours it; a row-wide mark says "something here matched" and leaves the eye to do the work the mark was meant to save. Registered as a `::highlight()` range rather than as spans, or a filename with three matching letters grows a real Taffy node around them |
| **`registerCommands` runs from `UINode`'s INSTANCE INITIALISER, so a per-INSTANCE registration placed there passes `null`** | Its own javadoc says fields are not initialised yet and calls the hazard deliberate, and it is still the shape that gets reached for, because the method reads as "where this widget wires itself up". `Workbench` contributed its `ProjectIndex` there, `ProjectSourcesRegistry.contribute` opens with `if (provider == null) return`, and the whole of M15 S4 was dead on arrival: every cross-file reference in the workspace reported *cannot be resolved to a type* while the registry, the name environment, the project tier and 2,533 tests were all correct. Nothing threw and nothing logged, because **"no provider" and "a provider that knows nothing" are the same answer from outside**. It is also once per CLASS, so even non-null it would register only the first workbench's index. Register per-instance things in the constructor; this hook may name statics only |
| **A CLASS-NAMED HOST NEEDS A `::part()` TWIN TOO, AND A SELECTOR SCAN THAT ONLY KNOWS TAGS WILL MISS IT** (M6.1) | `.__search-field__ .__field__` names the host by a CLASS the widget wears rather than by its tag, which is the right call there — the box's whole look is on that class so a caller can borrow it — and the twin generator only matched `tag .__x__`. Thirteen rules were skipped, including the one giving the field its height. **And the generator must be idempotent**: it appends a twin to the selector list while leaving the original in place, so a second run appended it again — `checkbox::part(mark)` three times over, which parses and matches identically and is pure noise. It dedupes on rebuild now, so re-running it is free |
| **`box()` IS NULLABLE, EVERY PORTED GEOMETRY READ ASSUMED IT WAS NOT, AND THE FIX IS NOT AN ACCESSOR ON THE NODE** (M6.1) | A node has a box only while connected, unfrozen, and neither `hidden` nor `display: none` — where the old `getRuntimeCache()` always answered. So 185 unguarded chains came across in the port, each an NPE the first time the thing it measures is switched off: `ScrollerView.reserveCorner` reads a scrollbar's thickness and a bar that is not shown has nothing to read. Found on the gallery scene's first run, which is what that scene is for. **The convenience fix was written and reverted**: `UINode.boxWidth()`/`boxHeight()`/`boxX()`/`boxY()` answering 0 is `getRuntimeCache()` returning under a new name — it puts geometry accessors back on the node the three-tree design took them off, and it throws away the one thing the null was carrying, because **"zero-sized" and "never laid out" are different facts**. Guard at the call site, where the widget knows which of the two it is looking at and what the right answer is: zero thickness for a bar that is not there, `false` for a thumb that cannot be under the pointer, an early return for a host with nowhere to put a marker. And never zero for a DIVISOR — `Math.max(1f, …)`, because a fraction of zero is a NaN and a NaN poisons a whole layout with nothing having thrown |
| **A LISTENER ON A SHADOW HOST CAN NEVER SEE ITS OWN PARTS — `event.getTarget()` is RETARGETED to the host before it runs** (M6.4) | The DOM's rule and this engine's: a listener outside a shadow tree sees the host, and a listener attached to the host IS outside its own shadow root — `UINode.retarget` walks up from the target and stops only at a root that is a shadow-including ancestor of the LISTENER, which the host's own shadow root never is. So the idiom the old engine used everywhere — one listener on the widget, an if-chain comparing `event.getTarget()` against its shadow parts — compiles, runs, and takes the wrong branch forever the moment those children become parts. `Scroller` fell through `thumb`/`head`/`tail`/`track` to `target == this`, whose branch jumps the thumb to the pointer: **a scrollbar that highlights under the cursor and refuses to move**, because a press ON the thumb jumps it to where it already is. Attach inside the shadow tree — a listener on the part is a shadow-including ancestor of itself, so nothing retargets — and `stopPropagation()` there, or the press bubbles to the track and the jump happens anyway. **A sweep finds this class mechanically**: any shadow-hosting widget that reads `getTarget()` at all |
| **`Box.x()` IS PARENT-RELATIVE WHERE `getRuntimeCache().getX()` WAS ABSOLUTE — so every ported subtraction of two boxes' offsets is comparing two different spaces** (M6.4) | The old accessor accumulated through every ancestor, so `a.getX() - b.getX()` was a legitimate way to ask "where is a, relative to b" for ANY pair. `Box.x()` is *"the offset from the host's border-box origin"*, so the same expression is only meaningful when the two boxes share a parent — and it is **silent** otherwise, wrong by an amount that depends on how deep in the tree they are. It killed the graph's wires: `NodePort.dotCenter()` returned a dot's few-pixel offset inside its own port row instead of its position on the plane, so every wire collapsed onto one short segment near the origin, drawn perfectly, in the wrong place, with the model entirely correct and the status line reporting the right count. **`Box.centreIn(box, space)` and `Box.originIn(box, space)` are the conversion**, through `space.worldToLocal()` — the only one that also carries the intervening transforms and scrolls, which a subtraction never did. Half-extents are added AFTER it, in the target's units: `worldToLocal` has undone every scale above `space` and a box's own width is unscaled, so adding them first scales them twice. **A sweep for `.x() - something.x()` finds the class mechanically**, and found five: the wire endpoints, the port editor's stub, the navigator's sidebar fit, `worldBoundsOf` (latent — the plane sits at the canvas's origin until a sheet gives it padding) and `visibleWorldRect`, which was wrong THE WHOLE TIME and is what culls both nodes and wires: it read the canvas's offset inside its OWN parent, so a canvas half way down a page reported a viewport hundreds of world units from the one it shows. **The viewport's own top-left is (0,0) in its own space** — the world point it shows is just the pan undone, and needs no box at all |
| **A COMMENT THAT EXPLAINS A COORDINATE SPACE IS A PORT HAZARD IN PROPORTION TO HOW GOOD IT IS — three of them in the compositor, each correct and each now inverted** (M6.6) | The M6.4 row above found one; the desktop had three, and they are the most carefully argued comments in the batch. `WindowMove`'s class javadoc, `snapZoneAt`'s method javadoc and `beginTearLoose` all recorded — at length, with the bug each was written for — that `screenToLocal` divided out the surface scale and did **not** subtract the element's own position, so a drag callback's coordinate was effectively ABSOLUTE and the work area's origin had to come off it. `snapZoneAt`'s own text says a previous version added the bar's origin back and "was therefore counting it twice", displacing the snap zone by however far along the desktop the window sat. Every word is true of the old engine. M6.1 moved the origin, so the arithmetic INVERTS: an offset along the caption needs no subtraction, and reaching the work area's space needs the caption's position ADDED — which reintroduces the documented bug from the other side. **The comment is what makes the line look considered rather than stale**, and a sweep for `.x() - .x()` finds none of these, because two of the three are additions on the far side of a comparison. Re-derive every coordinate site in a ported file from the engine it is landing on; do not translate one |
| **A CONCRETE CLASS METHOD BEATS AN INTERFACE DEFAULT, SO A FRAMEWORK HOOK MAY NOT REUSE A NAME THE BASE CLASS ALREADY HAS** | `Networked.mayClose()` was first written as `requestClose()`, and `UINode.requestClose()` already existed as the close-watcher hook — with the **opposite** sense, `false` meaning *"I did not handle this"* rather than *"do not close me"*. A panel is `extends UINode implements Networked`, so every one that did not override it answered `UINode`'s `false`, `mayClose` read that as a veto, and `WindowFrame.requestClose` returned without closing: **the X silently did nothing**, with no error anywhere. Shipped, and found by opening the game. **Every test passed** because each test panel happened to override the hook — which is the general trap with a default method, since the fixture that exercises it is exactly the fixture that hides it. The covering test is therefore a panel that overrides NOTHING, and it asserts both questions side by side so the distinction cannot quietly collapse again. Check a new hook's name against `UINode`'s public surface before adding it; `mayClose` was free, and the pairing with `ClientWindowContext.mayClose` is a bonus rather than the reason |

## The cascade

| Invariant | Consequence if violated |
|---|---|
| **The desktop's window layer is the WORK AREA, and it only means anything once it is `.__windows__`** | Its whole geometry is one CSS rule; without the class the layer sizes to content, its children are all absolutely positioned, and it measures 0x0. Nothing then fails — every rule that reads the work area is guarded against a zero box on purpose, so the clamp and the cascade both quietly stand down and windows land wherever they were asked to go. Cost a full test run to see, and the fix was one `addClass` |
| **A desktop-scoped close watcher is UNREACHABLE while any window is active** | `getTopCloseWatcher` asks the active frame's stack first and a frame registers as its own last watcher, so the frame itself always answers before anything registered outside a window. Escape aimed at desktop chrome therefore minimises or closes the window behind it instead. Anything that must take Escape at desktop level belongs on the **live-drag rung** in `consumeKeyboardEvent`, ahead of the cascade — which is the honest description of a window switcher anyway: it is held open by a modifier that is still down, so while it is up Escape can mean nothing else |
| **`ElementStyle.getComputed` answers NULL for a property nothing has written** — the initial value is not a candidate | So an element that has never been touched reports neither `FLEX` nor `NONE`, and a test asserting the default passes only by accident. Ask the question that every state can answer — "is it hidden" — not "what is its display" | **`ComputedStyle` (M5 5.2) is the answer that never nulls**: `ElementStyle.computed()` is an immutable snapshot where an unwritten property answers its initial and an inheritable one its parent's, cached with the parent's snapshot as part of the key. The box tree reads that; the old engine keeps reading `getComputed`
| **A SCISSOR RECT IS IN SCREEN PIXELS, so a target with its OWN coordinate space must not inherit one** — `CgUiBackdrop.withoutScissor` | Every ordinary layer FBO is screen-sized, which is why `beginLayerFbo` is right NOT to reset the clip: an element inside an `overflow: hidden` subtree must stay clipped when it is promoted. The backdrop capture and the blur targets are the first things here that render into a target sized differently from the screen, and for them the inherited rect is not a clip but a coordinate error. Glass drawn inside a clipped subtree got blur targets whose left strip was never written — the stage's clip began ~180px into a 1920px screen, and the same 180 landed 180px into a 480px target, so 37% of it stayed at the clear instead of 9%. Panels over that strip sampled transparent black and came out DARK, with a hard edge exactly where the rect began, growing with the radius because a wider kernel reaches further into the hole. **It presents as a sampling or clamping fault and is neither**: the arithmetic downstream was correct the whole time, it was being handed a target with a hole in it. Six rounds went into the sampling. A readback of the target found it in one |
| **AN 8-DIGIT HEX IN A SHEET IS `#RRGGBBAA` — alpha LAST — and the engine's int is `0xAARRGGBB`; a pin written in the int order is a DIFFERENT COLOUR at a DIFFERENT ALPHA, with no error** | `--taskbar-glass-tint: #EB1C1D21` meant (28,29,33) at 92% and parsed as pure red (235,28,29) at 13%, so the taskbar's Mica was a red wash over the blurred desktop — measured at (52,25,25) over a (25,25,25) editor, which is that mix to the digit. **It was written in the int order TWICE**: that pin replaced a shipped `#E01F2023`, which parses as (224,31,32) at 14% and had been washing the bar red since it was first authored, so the rewrite reproduced the fault it was standing on rather than inheriting it. Both preview pins and both themes' `--surface-glass` had the same slip. It survived because it still looked like *a* material, and two comments were written blaming saturation and the harness's red clear colour before anyone read the parser (`ColorValue`, `case 8: // #RRGGBBAA`). The tell is an alpha that makes no sense for the role: a 13% *base* surface, a 19% veil that reads as a colour. Every other 8-digit pin in the themes was already CSS order, which is what made the four wrong ones invisible in a list |
| **Never name a class `__content__` in a descendant selector** | Already stated on `CrystalEditor.CONTENT_CLASS` and `ProjectFileTree.CONTENT_CLASS` and broken a third time anyway. `ConfiguratorGroup` names its body that too, so `.__view-container__ .__content__` reached every group in every panel below it and zeroed their heights — chevrons open, content a sliver |
| **`font-size` does not inherit, whatever `setInheritable(true)` says** — `default.css` opens with `* { font-size: 10 }`, which is a candidate at STYLESHEET origin on *every* element, and inheritance only applies where there is no candidate at any origin | A rule on a wrapper computes correctly on the wrapper and the label inside it still renders at 10. `statusbarview .__status-item__` works only because the status item **is** its `UIText`; any widget that wraps its label — for padding, a hover fill, an icon slot — must put the declaration on the text element itself. Cost a probe on the menu bar, where `height: 22px` on the same selector applied and the `font-size` beside it silently did not |
| **A `font-size` written after the rules matched must re-resolve the `em`s** — `StylePropertyRegistry.FONT_SIZE` carries a listener that asks for a re-match | An `em` becomes pixels in `rematch`, and nothing else re-runs it. A widget imposing its own size at INLINE or IMPORTANT — which is what zoom does — appears in no rule at all, so without the listener every `em` on the element keeps the pixels it was given when the sheet last matched. Gated on a flag the engine sets during the match, so an element with no `em` pays one field read |
| **A policy filters the type index through a VIEW, and a member list on the way OUT** | The index is shared per classpath and holds fifty thousand entries, and the policy belongs to the asker rather than to the classpath — so `TypeIndex.filtered` wraps the answer instead of copying the index. `InteropResolver` filters after the probe for the same reason: the Java engine's answer about a class does not depend on the policy, so the cached analysis stays reusable and only the member cache is dropped when the posture changes. A member whose DECLARING class is refused goes too — an inherited `toString()` is still a call into the type that declared it |
| **A remap test's fixture must use INHERITANCE, not composition** | A mapping names the type that *declares* a member while a script holds whatever it holds, so the translation walks the hierarchy. A delegating fixture declares the runtime name itself and passes without exercising the walk at all — green against a translation that cannot see a supertype, which on a real deployment is nearly every call |
| **A prototype's members are NON-ENUMERABLE, so `getIds()` reports none of them** — `ScriptableObject.getAllIds()` is the accessor | `toString`, `valueOf` and `hasOwnProperty` are non-enumerable by specification, so reading `Object.prototype` with the obvious accessor answers an empty list and the inherited half of every member list vanishes without a symptom. `inheritedFromObject` then has nothing to mark, which reads as the flag being unused rather than as the ids being missing |
| **`core/`'s language SPI names no language's facts** — which type is the universal root (`java.lang.Object`, `Object.prototype`) is the engine's to say via `CompletionItem.builderFrom(symbol).inheritedFromObject(…)`, and every `SymbolInfo.with*` carries every field | `CompletionItem.from` used to compare the container against `"java.lang.Object"` inside core, and the withers routed through the seven-component constructor, so `of(...).withSignature(s).withType(t)` silently dropped the signature — an order-sensitive builder on a seam is a trap for exactly the engine that comes second |
| **`icon()` in CSS resolves the light/dark variant only through `CgUiSvg.ofIcon`** | `TextureValue.parseIcon` called `of(toResourcePath(...))` instead, so every `icon()` in every stylesheet drew the LIGHT file forever and a theme swap changed nothing. Invisible for as long as the shipped icons were `currentColor` chrome marks with no dark drawing, where `withVariant` falls back to the base file and the two spellings agree |
| A widget's cascade identity is its **tag**, never its Java supertype | `Dropdown extends Button` but `button {}` does not match `dropdown` — it laid out at zero height until `default.css` named it |
| `TransitionEngine` advances on `System.nanoTime()`, ignoring the delta it is passed | A test loop cannot step transition time; assert the inputs (resting value, state class, ANIMATION-origin candidate) rather than intermediate values |
| `requestFocus` is **PROGRAMMATIC and therefore rings**; pointer-driven focus must use `requestPointerFocus` | `:focus-visible` exists to ring keyboard focus and *not* clicks. A widget that focuses itself on press through the wrong one outlines its whole viewport on every click — which is the noise the pseudo-class was added to remove |
| A wire's colour is **read back out of the cascade** — `NodePort.typeColor()` returns the dot's computed `border-color` | `CgVectorRenderer` needs an ARGB int, so something must hand it a number; reading it from the dot keeps Unity's per-type palette in `graph.css` instead of putting GLSL's type system and its colours in Java. Hard-code it and adding a type means editing two languages |
| `nodeport:blank` means *unconnected*, and a connect must `invalidateStyleMatch()` | It drives both the hollow-vs-filled dot and whether the inline editor shows. Without the invalidation a pseudo-class is never re-evaluated: the dot stays hollow under a live wire and the editor stays visible beneath it, which reads as a paint bug |
| A `graphnode` paints **no background of its own**; each region paints one, and the port band deliberately paints none | That is what lets a wire — drawn under every node — show through and read as plugged into its dot rather than cut off at the border. The cost is that a region which forgets to paint is see-through, so the regions are named together in `graph.css` rather than left to inherit |
| The plane's `transform-origin` is pinned to `0 0` at IMPORTANT | It defaults to 50%, so every world↔screen conversion in `CanvasView` would be off by half a viewport times the zoom — and it would look plausible, since the picture is still internally consistent |
| A recycled row must **swap** its data-driven classes, never merely add them | A template is a different row every time the view reuses it, so adding `filetype-java` without removing `filetype-md` leaves both on the element — and the cascade then resolves whichever rule happens to win, which reads as a random colour rather than as a stale class. Same for `decoration-*`. `ProjectFileTree.swapPrefixedClass` is the one definition |
| A compound selector carrying `::highlight()` must never match the originating element | Every highlight colour repaints the whole paragraph — and looks plausible, because the highlighted words are the right colour too |
| Pseudo-elements weigh **1** (type component), not 10 | Wrong by analogy with pseudo-classes; a `::highlight()` rule then silently outranks the class rules around it |
| **`::highlight()` CAN paint a background band, and the geometry was in the layout all along** | It sat in `NOT_YET_PAINTABLE` on the grounds that a band needs per-range rects and a `CgStyleSpan` carries nothing positional. Both true and beside the point: shaping breaks a run at every span boundary, so a highlighted range **is** one or more `CgShapedRun`s and each carries `sourceStart`/`sourceEnd`/`totalAdvance`. `UIText.paintHighlightBands` walks them — no measurement, no second shaping pass. `text-shadow` stays refused because it is a second *draw* of a range rather than a rect behind it |
| **`min-height` is a DIFFERENT PROPERTY from `height`, so a base rule's minimum beats any size you write at higher specificity** | `button { min-height: 14px }` held the search toggles open at 14px through three rounds of shrinking `height` — 13, then 12, then 10 — with nothing in the cascade to look at, because the rule that was winning was not competing for the same property. The chip stayed exactly as tall as the field's interior every time. Anything restyling a `button` into a compact glyph has to clear `min-height` **and** the base padding, not just set a size |
| **`:disabled` and `:hover` tie on specificity, so the LATER rule wins** — a disabled control written above its own hover rule still lights up under the pointer | Both are one pseudo-class (10). The find bar's match arrows were correctly `setEnabled(false)` and correctly styled, and still looked live the moment the cursor touched them. Put the disabled rule after the hover one and repeat it for `:disabled:hover`. Also: `button:disabled` repaints the whole face, which is right for a labelled button and wrong for a glyph — dim the glyph instead |
| **A disabled control must leave HIT TESTING, not just gain a `:disabled` rule** | `:disabled` and `:hover` tie on specificity (one pseudo-class each) and a `:disabled:hover` compound does not match here, so a disabled button kept lighting up under the pointer *and kept showing its tooltip* — a dead control explaining what it would have done. `setHitTest(false)` alongside `setEnabled(false)` means `:hover` can never match and no boundary event fires, which is what a disabled control should do anyway |
| **ESCAPE IS A CASCADE — a control must stop consuming it once it has nothing left to do** | The engine already applies this at the top (a live drag eats Escape before a close watcher; a nested popover before the modal behind it), and any control that takes Escape owes the same courtesy. A **permanent** search bar clears its query on the first press and must let the second through, or whatever contains it can never be closed from the keyboard — the settings dialog swallowed every Escape, because its search is permanent and always focused |
| **State a widget flips from its own listener belongs on a CLASS, not a pseudo-class** — `:checked`, `:disabled` and `:hover` have all now cost a round each | The engine re-evaluates a pseudo-class on its terms; a class is re-evaluated on yours. The search toggles use `__on__`, the dead match arrows use `__off__`, and both were written only after the pseudo-class version was styled correctly and still drew the old state. `invalidateStyleMatch()` is protected, so there is not even a way to force it from outside |
| `::highlight()` accepts only non-layout properties, enforced with a warning | The restriction *is* the feature: a highlight that could set `font-size` would reflow the text being searched as you type |
| `text-overflow` does **not** inherit — it must sit on the `UIText` itself | Set on a wrapper it silently never arrives, and the row renders as plain `clip` (`white-space` *does* inherit, which masks it) |
| **The Gradle sibling-directory search must be GATED on the directory looking like a cache entry** | It exists for one layout — `…/version/<sha1>/foo.jar` beside `…/version/<othersha1>/foo-sources.jar` — and is waste everywhere else. A `mods/` folder is the case that matters: three hundred jars share one grandparent, so an ungated rule runs the same directory listing three hundred times on the first hover of every launch and then offers `config/foo-sources.jar` and `saves/foo-sources.jar` as candidates. Forty hex characters is the test, it is one string comparison before any filesystem call, and nothing but Gradle names a directory that way |
| **A BATCH'S DEFERRAL CASCADES, and the audit question is what a class names that is not SHIPPING — not what it names that is not LOCAL** (M6.4) | 6.4 was planned to defer two classes to 6.7 by scanning for imports pointing OUTSIDE the batch. `ShaderInspectorSections` imports nothing outside it and names `ShaderGraphEditor` four times, which is inside the batch and deferred — so it defers too, and the count was wrong until the compiler said so. The same shape will recur in every batch that holds anything back: a deferral is a property of the SHIPPING SET, and a scan keyed on directory boundaries cannot see it |
| **OPENABILITY IS A FACT ABOUT A DEPLOYMENT, NOT ABOUT A CLASS** — so it is declared at registration and never on the `UiType` | The same panel may be openable on a test server and not a live one, for some players and not others. On the type it becomes a property every consumer of that class inherits, and a mod wanting the other answer has to write a second class. Declared per server, the resolver is handed the **viewer** and can differ per player with no second mechanism. **The default is refusal**: a client able to open any registered type could open a panel over a block it is nowhere near, or one a mod only ever shows from its own code |
| **EVERY STATE SETTER MUST BE IDEMPOTENT, because "mirror the model each tick" is the shape every server-side panel is written in** | `MachinePanel.mirror`'s javadoc states the rule — an unchanged value writes no candidate and marks nothing dirty, so mirroring more often than necessary costs comparisons rather than traffic — and `ProgressBar.setFraction` was the one setter for which it was **false**: it called `notifyStateChanged()` unconditionally, plus `invalidateStyleMatch()` and an IMPORTANT-origin write. So a panel mirroring a bar every tick sent a `ui/stateDelta` **per tick, forever**, carrying a value nobody had moved, and re-ran selector matching on the element every frame. Hidden for as long as every panel gated its mirror behind a dirty flag of its own — which is what makes it a trap rather than a slip, because the flag is the thing the rule says you should not need. The first panel to mirror unconditionally, on exactly those documented grounds, turned a quiet window into constant traffic **and nothing failed**: every one of those deltas carried the correct value. Assert on TRAFFIC (`InMemoryTransport.sent()`), never on state, or the test passes against the bug. `Dropdown` was checked and is fine — `select` guards, and `addOption`/`clearOptions` genuinely mutate. And the guard needs a `applied` flag rather than a bare equality test, because `ProgressBar`'s CONSTRUCTOR calls `setFraction(-1f)` while the field already holds `-1f` |

## Layout, flex and CSS in the sheets

| Invariant | Consequence if violated |
|---|---|
| **The desktop is engine-owned and must take up NO SPACE until a window is open** — `UIDocument.desktop()` builds it, nothing else may, and `Desktop` sizes itself from whether it holds a frame | It is an overlay over the application's own root, so a full-size empty one hit-tests across the whole window and eats every click that lands on background: a UI that never opened a window simply stops responding, and nothing about that symptom points at a compositor. The mirror case is the one that bites later — the LAST window closing has to give the surface back, or a desktop that was used once keeps the application dead |
| **A drag never completes a click, so the thing being dragged is never SELECTED** — select on the press | The pointer moves, so no Up lands on the element the Down went to, and the selection a click would have made never happens. Dragging an unselected tab therefore lit **two** tabs at once — the selected one, and the one being carried, which click-focus had just outlined — and dropped it as a background tab. Both references select on press. Safe to do mid-dispatch here only because `DockGroup.sync` rebuilds its strip when the panel LIST changes and not when the selection does; the general rule against rebuilding what you are being clicked on is unchanged |
| **WHAT GL PERMITS IS NOT WHAT THE HOST TOLERATES: Blaze3D MODELS TWELVE TEXTURE UNITS, AND `CgBindingPoints` WAS ALLOCATING FROM THIRTY-TWO** | The engine reserves its binding points by counting DOWN from `GL_MAX_TEXTURE_IMAGE_UNITS`, so on a 32-unit driver they land on 31/30/29/**28** — legal by both per-stage limits, which report 32 here. Minecraft does not model them: `GlStateManager` keeps a twelve-entry texture table and caches the active unit beside it, so binding above it leaves the driver in a state its shadow cannot represent. **The damage lands on whoever samples UNIT 0 next, which in an embedded renderer is nearly every draw.** A sampler that misses its texture draws its DECLARED DEFAULT, and the two defaults fail in opposite directions: `gui_layer_blit` declares `_MainTex = "white"`, so a premultiplied composite FLOODS — a right-click turning the whole screen white — while a dark default ERASES, which is a text editor drawing its background and none of its content. Four unrelated-looking bugs from one integer. **Bisected, not reasoned**: unit 11 renders and unit 12 does not, and an ordinary colour texture breaks it exactly as the depth attachment does, which rules out depth formats, shadow compare and sampler types. **The ceiling is DERIVED FROM Blaze3D at runtime** (`Blaze3dTextureUnits` reads `GlStateManager.TEXTURES.length`, falling back to 12 and logging which) and declared by the LOADER through `CgCapabilities.setHostTextureUnitCeiling` — from `PlatformService1201.gl()`, because `onContextInit` is never called on this loader (the context initialises lazily from `onOpaquePass` on the first world render, so a hook there looks right and never fires). Unclamped elsewhere, so the harness and 1.7.10 keep the whole range. **Three cheaper fixes were tried and are wrong**: withholding `cg_DepthBuffer` from `prepareFrame` works until a UI shader wants scene depth; moving ONE consumer off unit 0 fixes only that consumer (the editor and menus came back and the rest of the theme did not, which is what proves the corruption is of unit 0 generally); and neither of the state shadow's elisions is the cause — disabling each in turn changed nothing, and unit 0 measurably held the right texture at draw time. **The mechanism below the boundary is NOT established**, and saying so is the point: what is known is the boundary, that it is the host's and not the engine's, and that it is read rather than guessed. A reported second cause -- `CgGlGetProvider.readTextures` failing to record the active unit -- was a MISREAD of a truncated listing; the assignment was always there, which is why "fixing" it changed nothing |
| **THE HOST'S FIXED-FUNCTION ALPHA TEST IS ON, AND IT DISCARDS EVERY UI FRAGMENT UNDER 10% ALPHA** — `Minecraft.startGame()` sets `glEnable(GL_ALPHA_TEST)` + `glAlphaFunc(GL_GREATER, 0.1)` and leaves it there | A compatibility profile applies that test to programmable-pipeline draws too, and NOTHING on our side models it — `CgRenderState` carries blend, depth, cull and stencil and no alpha — so a material neither sets it nor clears it and whatever the host left on governs every quad, glyph, gradient and glass surface. Not dimmed: **cut**, with a hard edge exactly where the alpha crosses the reference. Measured on the taskbar's glow, `linear-gradient(90deg, transparent 18%, #3574F033 50%, transparent 82%)` across a 1999px bar: a hard-edged band from x=642 to x=1347 with the ramp INSIDE it exactly right and both ends cut at α≈0.105. So axis, stop positions, premultiplied interpolation and the one-draw window were all correct and the picture was still wrong — six of the seven things one checks first are the gradient's. **The harness cannot see it by construction**: LWJGL3 has no fixed-function alpha test to leave on, so the identical CSS is correct there and no scene, probe or readback can reproduce it. **What it reaches is a fragment's OUTPUT alpha, never an alpha in the CSS**: a `glass()` tint at 7.5% is an input to a mix inside the shader and the surface still writes its coverage, so the acrylic panels were never affected. The ones that are: a `background-color` at or under 10% (Fluent's subtle fills, 6% and 3.5%, discarded whole), the transparent shoulder of any gradient, the outermost sliver of every anti-aliased SDF edge, and the opening frames of any layer composited at a low opacity — so it reads as "the translucent parts are missing" or "the soft edges are hard", never as one GL flag. **Disabled TWICE per frame**, because `endFrame` closes the frame's scope before the composite: the frame's disable protects each element's fragments, the composite's protects the finished picture, which is clipped by ACCUMULATED alpha and would take a 7% panel away whole rather than cutting its shoulders |
| `flex-shrink: 0` means a `flex-grow: 1` child **overflows its parent** rather than shrinking — give it `height: 0`/`width: 0` as its basis | The child keeps its content size and anything stretching to that size spills with it. Cost a real session on the gallery: `__panes__` overhung the frame containing it, and only at small window sizes, because at large ones there was room. `FlexShrinkOverflowTest` pins both halves |
| **The fill idiom is `width: 100%; height: 0; flex-grow: 1`, and it never touches `flex-shrink`** | The corollary of the row above, and it caught three separate things in one session: the dock, a `RegionHost` and a `ViewContainer` each measured to nothing until they carried it. Overriding `flex-shrink: 1` to "help" does the opposite — the `0` default is what stops content being compressed below its own size, and with shrink on, every `ConfiguratorGroup` in the Inspector collapsed to a sliver. `.__inspector__` and the dock's pane host are the reference spellings |
| **A `SplitView` pane is a flex COLUMN regardless of the split's orientation**, so a pane's child always grows by height | Reasoning from the split instead — "this one is horizontal, so grow by width" — collapses whichever guess is wrong, and it fails as a *sibling* problem rather than a sizing one: the sidebar measured zero, so the file tree's rows existed and could not be clicked |
| **A `SplitView` cannot go below two panes, and a surplus pane cannot be made to occupy nothing** | `removePane` refuses and returns `false` — looping on it never terminates, which killed a test worker outright. And neither escape works: `applySplit` writes `flex-grow`, which only divides *free* space, while `setPaneSizeLimits` clamps *dragging*. The answer is to not use a split for one part — see `WorkbenchRegions.single` |
| **`flex-grow` summing to less than 1 leaves the remainder undistributed** | Not a bug, the flexbox rule. Weights authored as fractions of the whole sum to 1 only while every one of them is present, so it looks correct until one is hidden — then that fraction of the row is simply blank. Normalise before applying |
| **`gap-all` applies between EVERY pair of children** | Which is wrong the moment two of them are one thing: it put a space inside a signature — `arraycopy (Object, int, …)` — reading as two controls rather than one name. A gap wanted in exactly one place is a margin there, not a gap on the parent |
| `System.nanoTime()` has an **arbitrary origin and may be negative** — never use `Long.MIN_VALUE` as a "long ago" sentinel against it | `nanoTime() - Long.MIN_VALUE` overflows to a *small* elapsed time, so "never merge again" evaluates as "merge immediately". Caught here by a test; in the wild it is undo swallowing two actions on some machines and not others. Use an explicit flag |
| A leading resize derives its origin from the size **achieved**, never from the pointer delta | The box shrinks to `min-height` and then keeps travelling — while the trailing edge, which moves nothing, correctly just stops |
| **A flex item with `flex-shrink: 1` contributes ZERO to its row's min-content width** — and an explicit `width: 0` basis on a `UIText` latches it as "does not size itself", permanently | Invisible while rows are stretched to their container, because nothing asks what a row's content width is. It surfaces the moment one is sized to content: the Blackboard's rows scroll sideways for a long name, and the type column — carrying both — left the row exactly as wide as the capsule, so `Vector 2` rendered as `Ve…` jammed against the panel edge, *outside* the scrollable width the long name had just created. `UIText.forceSelfSizeWidth()` exists for the second half; the first is `flex-shrink: 0` |
| **`getScrollWidth()`/`getScrollHeight()` measure direct children only** — a descendant overflowing its parent adds nothing | Deliberate and cheap, but it means "make the content scrollable" is a statement about the *rows*, not about what is in them. A capsule spilling out of a full-width row painted over the canvas behind the panel and reported `maxScrollLeft: 0` — there was no way to reach it, by bar or by wheel, because nothing knew it was there |
| A highlight property that resolves but is never painted is worse than one refused — `HighlightStyle` splits `ALLOWED` from `NOT_YET_PAINTABLE` | `background-color`/`text-shadow` sat in the allowed set doing nothing; the rule looked right, the band never appeared, and there was nothing to search for |
| **A hidden child still counts for a `gap-all`** | `SearchField`'s option strip was a permanent child hidden with `display: none` when empty, and every existing consumer — palette, create menu, Blackboard — silently gained a gap; the Blackboard's overflow tests caught it. Create the container on first use instead: not existing is the only spelling of "costs nothing" that is actually free |
| **The fill idiom in a ROW is `width: 0; flex-grow: 1`** — neither `flex-grow` alone nor `width: 100%` works | Already stated for columns and it is the same rule sideways. But check the PARENT first: a bar with no `width` is sized to its own children, so its width *is* their width and there is no free space in it at all — every flex property tried on the child does nothing, and the row was never short of a rule, it was short of a parent |
| **`background` and `background-color` are SEPARATE properties — a rule that sets only the colour is painted over by whatever drawable won** | `button:hover` shipped with `background: #FF0000`, a placeholder nobody saw while every button was a labelled rectangle. Used as small glyphs in a row it was unmissable: the search toggles flashed red under the pointer and stayed red while focused, *through* a `:hover` rule that set `background-color` to a grey. Restyling a button state means setting both — `background: none` to drop the drawable, then `background-color` for the fill |
| **`flex-shrink` defaults to 0 here, so in any packed row exactly one element absorbs every squeeze** | The find bar put it on the input, so in the Preferences sidebar the count and the mode button stayed rigid and the *box* collapsed to ~40px — four characters of query rendering as `nt`. A control that can shrink to nothing is not a control: the input needs a `min-width` floor and something else in the row has to be the thing that gives (here, the count, which is the one part losable without losing the control) |
| **`Integer.MAX_VALUE` is how `Diagnostic.onRow` spells "to the end of this line", so a column is clamped BEFORE it is added to an offset** | `at + column` overflows to a negative number and the whole mark collapses to a point, which reads as a diagnostic that was never widened rather than as arithmetic. `Rope.pointToOffset` has a test named for this; the runtime-problem lane became its second reader and repeated it |
| **A SLOT IS AN ORDINARY BOX, SO IT SHRINKS TO ITS CONTENT UNLESS TOLD OTHERWISE** (M6.1) | `ScrollerView`'s viewport slot measured **42px inside a 776px scroller**, because this engine's `flex-shrink: 0` with an `auto` basis sizes a box to what is in it. A caller's `width: 100%` row then resolves against the slot rather than against the view, so every row came out the width of its longest word — which reads as the rows being unstyled rather than as the box around them having collapsed. The slot is `width: 100%` at DEFAULT origin now, and its HEIGHT is deliberately left unconstrained: content must be free to exceed the viewport, which is the whole point of a scroll container |
| **A CONVENTION MAY NOT GUESS WHICH SLOT A WIDGET MEANS — the contract has to declare it** | `Slider` carries `MIN`, `MAX`, `STEP` and `VALUE`, all four of them floats, so neither "the first slot" nor type matching can choose — and declaration order deliberately puts the range FIRST, because a value applied before its range is clamped against the old one. A convention that guessed would therefore be wrong on the widget it is most useful for. `WidgetContract.primary()` is the declaration and `null` is a real answer: `Dialog`'s title, `SplitView`'s weights and `Popover`'s mode are not "what the widget is" the way a slider's value is, so those are REPORTED as unwireable rather than assumed |

## Input, focus and dispatch

| Invariant | Consequence if violated |
|---|---|
| **Modality is scoped to the WINDOW, and the scope is an element's nearest `WindowFrame` ancestor** — a modal outside every frame still blocks the whole document, which is what desktop chrome's own dialogs need | Enforced at the same **four** points the unscoped version was (hit-testing, Tab, `requestFocus`, the top-layer skip), and Tab needed a second half it never used to: scoping traps Tab inside a modal when the focused window is the blocked one, and a modal in *another* window traps nothing — so the walk must also skip what it blocks, because `tabbable()` sees only the inert ATTRIBUTE (deliberately, so its cache stays valid) and has no objection |
| **A drop position is RAW SURFACE PIXELS; a float's insets are its OWNER's local space** | Two conversions apart, and both place the window neatly somewhere wrong — the raw position is out by `uiScale`, and the drop overlay's own local space starts below the caption and inside the rails. `containsScreenPoint` is the giveaway for which kind of coordinate a listener is holding, the same tell the drag-callback rule already records |
| **A maximised window restores on the first MOVEMENT of a drag, never on the press** | Restoring on the press means the first press of a double-click restores and the second re-maximises, so double-clicking a maximised caption appears to do nothing at all — the two gestures share one listener. Windows agrees: click-and-hold on a maximised title bar does nothing there either, and it is the movement that tears the window loose |
| **A window's own edges belong to its eight resize handles** — anything pressing "just inside" a frame in a test or a fixture hits `__resizer-left__`, not the content | The handles are absolutely positioned over the border box and hit-test first, which is correct. It presents as an activation or focus bug: the press lands, focus walks up to the frame (a resizer is not focusable), and the control four pixels away never sees it. Press an element's CENTRE |
| **A floating panel that animates ACROSS its own anchor steals the hover from it** | A taskbar preview rises from below its resting place and is promoted to the top layer, so for the first part of every entrance it covers the entry it belongs to and wins the hit test. The entry's `:hover` blinks off and back on as the panel passes, the panel's own hover rules churn with it, and — worse — the leave logic runs against a pointer that never went anywhere. Unhittable for the duration of any motion, restored when it settles: a control you cannot aim at yet is not a control |
| **An OWNED window has no desktop to activate against, and a press must still focus it** | `attachOwned` parents a frame into its owner's overlay slot and deliberately makes it no desktop citizen — no registry, no taskbar entry, no z of its own — so `Desktop.activate` early-returns on the null owner and the press did nothing at all. Focus is the whole of what activation means for a window with nothing to raise and nothing to announce. It matters most for a DRAG, which is how it was reported: a drag never completes a click, so the press is the only moment there is |
| **A full-size overlay is safe to make HITTABLE exactly when it is `display: none` whenever it is not drawn** | The standing fear is right and is this codebase's most-repeated failure — a transparent element covering the root swallows every click and nothing on screen says why. But the cure is not permanent `setHitTest(false)`, which also means the overlay's own controls can never be used: the switcher's tiles need hover, a press and a close button, and a control you cannot aim at is not a control. What makes it safe is that the element takes no box at all for every frame it is not on screen — which for a switcher includes the whole 150ms delay and therefore the whole of a fast tap, so there is no window in which an INVISIBLE one can eat a click. `display` rather than opacity is doing double duty here: it is also what keeps a full-screen element out of the layer-FBO path |
| **A gesture that must work ANYWHERE inside a window takes the press in the CAPTURE phase — the bubble phase sees only what nothing else consumed** | Alt-drag is "drag the window from anywhere", which means over a button, an editor, a tree row — every one of which consumes a press. A bubble listener on the frame is therefore a listener for the gaps between controls, which is precisely the case Alt-drag exists to escape. Capture also has to `stopPropagation()`, or the window moves AND the thing beneath it is clicked. The modifier itself is read from the **desktop**, never named in the widget: Alt is contested territory (`TextField` refuses Alt chords, `MenuBarView` claims Alt+letter) and a widget is the wrong place to decide |
| **`contains` on a Gson-serialised record is vacuously true for any string with an apostrophe** | Gson HTML-escapes by default, so `'` is written as `'` and a test asserting a record does NOT contain `"Someone else's"` passes against every implementation including one that writes it. Survived two mutation rounds looking like a filtering bug. Assert on a string with no `'`, `<`, `>` or `&` — and pair every "is absent" with an "is present" positive control, or a writer that produced nothing would satisfy it too |
| **A window is activated a frame BEFORE content that builds on a deferred rebuild exists** | `openWindow` raises and activates, and activation focuses — but a `DockArea` builds its groups in `tickFrame`, deliberately never inline. So at the one moment `focusDelegate()` is asked, `activeGroup()` is null, there is no tab and no content, and the delegate falls back to the dock itself: the bug it exists to prevent, arriving through the back door. The answer has to be given **twice** — at activation, and again the first time the layout says there is something to give it to. Found only by printing the delegate's inputs; a fix that reads correctly and never fires looks identical to no fix |
| **A band derived from a hideable element vanishes with it** — `DockGroup.stripBandContains` read the FIRST TAB's box | Fine until a tab could be withdrawn for the length of a drag, at which point dragging the only tab in a group made the strip's band zero-height: the drop fell straight through it and offered to SPLIT the pane instead of reordering. The strip's own box is both the fix and the more honest band, since it includes the scrollbar row reserved under the tabs |
| **A WIDGET DECLARES ITS OWN RATE, because the right answer is a property of the INTERACTION** | A `TextField` fires per keystroke and a `Slider` per pixel of drag, so a server-side panel that simply forwards them sends a packet per keystroke — and the handler author has no way to know that without reading the widget. Phoenix LiveView puts `phx-debounce`/`phx-throttle` in the markup for the same reason. **`commitOnRelease` is the half that makes throttling safe**: dropping intermediate values is fine and dropping the LAST one is data loss, so a slider released between ticks would otherwise report a value that is not where it ended up |
| `Enter`/`Leave` dispatch to every element in the entered/left chain | A container with children never receives hover events at all |
| `setHitTest(false)` applies to the whole **subtree**, like CSS `pointer-events: none` | A transparent container is transparent everywhere except where its content is — hit testing looks random |
| While a pointer is captured, no boundary events reach anything else | `:hover` flickers across every element a drag crosses |
| **A find bar closes when DISMISSED, never when its query happens to be empty** | Driving visibility from `!filter().isEmpty()` means backspacing the last character hides the box out from under the caret, so a query can never be cleared and retyped. VS Code's find widget stays until Escape or its close button; IntelliJ's speed search vanishes because it is a transient popup rather than a bar you can click into |
| **A blur raised by ROW RECYCLING is not a user gesture** — ask `ListView.isRecyclingRow()`, never assume | `recycle()` blurs a row before pooling it, deliberately and for a defect of its own, and at a listener that blur is indistinguishable from the user clicking away. Anything putting a focusable control in a row and treating lost focus as a decision has to ask. A flag the *widget* sets around its own `refresh()` calls cannot work: five call sites reach `treeView().refresh()` directly, so the list is the only thing that knows |
| **A row's inline editor is primed ONCE PER EDIT, never once per bind** | `bind` runs on every refresh — a listing arriving, a decoration changing, auto-reveal following the active tab, a fold — so priming there re-set the text, re-took focus and re-selected the stem several times a second. The reported symptom was a flicker; the real one was that the field could not be typed in at all, because the caret was put back every frame. ## Rendering, GL and shaders

| Invariant | Consequence if violated |
|---|---|
| **A `Pass` helper must be declared ABOVE `void vertex`, and a shader that FAILS TO COMPILE still runs its pass** | The material compiler hoists the region of a Pass body above `void vertex` into both generated stages; anything written between `vertex()` and `fragment()` reaches the vertex source only. A fragment helper placed there fails the FRAGMENT compile with `undefined variable "cg_tap"` — and every property it touches is reported undefined with it, so the error list reads as though the Properties block were broken rather than the layout. The second half is what makes it expensive: a failed compile is not a failed draw. The pass still switched targets, still cleared, and still submitted, so the blur targets came out part clear-black and part fallback-white — on screen a panel with dark regions and blown-out ones, indistinguishable from a sampling bug. **The compile error was in the harness log from the very first run**, and was never read because the log was tailed rather than searched |
| **A `withMaterial` body must not FLUSH — the properties it sets are uploaded by the bind AFTER it** | `applyProperties` is CPU-only and `withMaterial`'s second `useMaterial` is what uploads; a `ctx.flush()` inside the body draws the queued quads against whatever the PREVIOUS bind uploaded. The gradient's first version drew a quad per stop segment that way, and every segment took the colours of the segment before it — a wrong picture with no error, and one a single-segment gradient cannot show. Set properties inside the body (as `CgUiRoundedRect` does) or before the call (as `CgUiGlass` does), submit, and let `withMaterial` flush. The corollary is that a drawable needing several property sets is several `withMaterial` calls, which is what pushed the gradient to evaluate all its stops in ONE draw |
| **The diagnostic tracking hangs off `DiagnosticSet.onChanged`, never off the engine's push** | The shader graph writes four owners of its own on every compile and has no version to offer, and a future linter will be a fifth. Wiring the tracking to the engine covers only engine-reported problems and leaves every other producer silently untracked — the failure mode that looks exactly like the feature working |
| **...and on a SHARED workspace the same boundary decides whose it is: view state must never reach the file, or one person's is everybody's** | The row above is that line drawn for Ctrl+Z; this is the same line drawn for a second reason, and it is the one that bites once more than one person is on a server. A shader graph wrote its pan, zoom and floating-panel rects into the DOCUMENT settings, so `encode()` carried them and every save put one reader's camera into a file everybody opens. Three faults from one cause: whoever saves last imposes their view on the next person, two people editing conflict over a field NEITHER touched, and a three-way merge has to be resolved over somebody's viewport. It looks harmless while one person is testing, which is the whole difficulty. The seam is `DocumentEditor.writeViewState`/`readViewState`, which the session stores per client — the same one a text editor's caret, scroll and folds already use. **`encode()` is the only route anything has to a shared file**, so the sweep is finite: check every `DocumentModel`, and the ones already clean (text, bytes) are clean by having nothing to add. | **A panel's FILTER and its SEARCH must share one notion of "matches"** | The Problems filter read diagnostic messages while the search treated a heading as searchable by its FILE NAME, so `g` listed both shadergraphs and `graph` listed one: `new.shadergraph` has "graph" in its name and not in its message, so the row the search would have marked was filtered away before the marking could run. Two matchers in one panel disagree the moment a query hits only one of them |
| **Pass the SearchQuery, never the text** — the type that carries the options is the type the matcher takes | `TreeSearch.Model.setQuery` took a `String`, so every model rebuilt its own query and silently dropped Match Case, Words and Regex: `GRAPH` with two toggles lit still matched `shadergraph`. Handing over the text is the shape that lets a caller lose half the query, and it recurred in three places at once — `ProblemsTreeSource` (a private `toLowerCase().contains()`), `WorkspaceTreeSource.setFilter`, and `Preferences.matches` rebuilding one from `navigator.query()` |
| **A filtered TREE must match only what is written on the row — searching DESCRIPTIONS is a ranked-list affordance** | `ge` kept Appearance, Shaders and Workbench because their settings say "arran**ge**ment", "Percenta**ge**" and "chan**ge** it". Every hit was real and none was visible, and an unexplainable row in a tree is indistinguishable from a bug — it was reported as one twice. IntelliJ indexes them and *tells you* it did. Until there is somewhere to say so, match the label (the setting's name — what people type) and not the prose about it |
| A `.shader`'s `#include` reaches the **vertex** stage too — fragment-only lib code must self-guard with `#ifndef CG_VERTEX_STAGE` | NVIDIA compiles it and AMD refuses, so the UI is fine here and completely unlaunchable there |
| A failed material compile latches (`hasCompileFailed`) and is cleared only by `markDirty()` | Without the latch every draw retries the compile — 3044 log lines a second; without the clear, hot-reload can never fix a broken shader |

A forged out-of-range slider value is CLAMPED and delivered, because the clamped value is one a user could have made — so the handler runs and the model stays sane, where refusing would need a second channel to explain itself and make every handler defensive. A disabled element, an inert one or a kind nobody asked for is REFUSED, because no gesture produces those: the report came from a client that is wrong or a peer that is lying, and the safe reading is the same for both. **The sanitizing belongs to the WIDGET** — a slider's bounds and step, a field's maximum length, a dropdown's option count are known nowhere else, which is precisely why it cannot live in the session. `NaN` is the case worth naming: `Math.max(0, Math.min(1, NaN))` is `NaN` and a model's `==` guard is false against it, so the model is poisoned and every viewer's bars read `NaN` for good |
| **A RATE POLICY MAY DROP INTERMEDIATE VALUES AND MAY NEVER DROP THE LAST ONE** | Which is the whole difference between a debounce and data loss: a slider released between ticks would otherwise report a value it was merely passing through. So a held report is never discarded when a newer one lands, only replaced, and it is always eventually sent. **Driven by the CONNECTION's tick**, because a client session riding one does not own a tick of its own — a held value with nothing to flush it never leaves at all, and the failure is a control that works except when you stop moving it |
| **A HOOK NAMED FOR A STATE SAYS NOTHING ABOUT WHEN IT RUNS** — `bound()` became `bindWidgets()` | The salvageable half of D9's merge. Both hooks stay, because they genuinely run at different times, and what was actually wrong is that `bound()` named a condition the panel is IN rather than the job to do in it — so nothing in the name said "attach your widget listeners here, again, every time the tree is replaced", which is the one thing a reader has to know or their listeners end up on widgets that no longer exist. `bindWidgets()` says it, and reads as the counterpart to `client(io)` running once |
| **A LISTENER ON A MODEL OUTLIVES THE WINDOW THAT REGISTERED IT** | `bind` connected to a model `Property` and dropped the returned `Connection`. The model is the long-lived thing, so the chain runs model → listener → widget → whole window tree, retained for good after close. The ordinary shape of a listener leak, and the ordinary fix: keep the connection and disconnect it where the window ends. Worth pairing with `Projections.close()` — a projection holds the model, the widget and its last value, and a keyed one holds every realised row, none of which is a leak while the window is discarded whole, but all of which is only true rather than assumed once something says so |

| **`isPackage` cannot be delegated to the classpath on an obfuscated host** — a name that is not a TYPE is a package | There is no `net/minecraft/init` directory anywhere in an obfuscated jar; the package exists only after the deobfuscating transformer runs. ECJ asks about **each segment of a qualified name before it looks the type up**, so the delegate's "no" stopped every script with `net.minecraft.init cannot be resolved` — every Minecraft type, on the one environment that is production. A classloader cannot enumerate what is under a prefix, so the inversion is the only answer available, and it is sound in the direction that matters: the source can say definitively that something IS a type. A misspelling then reports as an unresolvable type, which is the better message anyway |
| **A script-level `fun` in `.gradle.kts` must be declared BEFORE its use** | The script runs top to bottom, so a forward reference to a helper does not resolve — unlike a class, where method order is free |
| **The band loader is opened ONCE per process (`EngineHost.shared`) and every language reaches its adapters through it** — `JavaEngine.over(host)` borrows, `JavaEngine.open(band, source)` owns, and only the owner closes | ECJ and Rhino ship pinned together in one band configuration, so a JavaScript engine that opened its own `EngineClassLoader` would be a second copy of twenty jars and a second identity for every type they share. Closing a borrowed host is how the *other* engine fails with a `NoClassDefFoundError` on a class it loaded fine a moment ago |
| **A CALL is a receiver, and BOTH engines got it wrong** — `list.get(0).` / `Files.emptyList().` put a `)` immediately before the dot, where no identifier covers the offset | Reported from the harness as "completion is flaky in places", which is what an EMPTY POPUP looks like: the popup opened, so nothing read as broken. JavaScript's `resolveAt` looked only for a `Name`; Java's walked up for a `SimpleName` and a closing bracket has none above it. Both now resolve the enclosing EXPRESSION and take its type — a call's type is its callee's, which composes to any chain depth. The Java gap was found only because a JS fixture caught it there first and the test was copied across: "it works in the other engine" is a claim, not a test |
| **A stale `language/build/classes` presents as "the engine band loaded, but the adapter could not be instantiated"** | `EngineHost` puts our own class files on the band loader's URLs, so a half-written output directory makes the adapter unlinkable — the observable failure is `NoClassDefFoundError` on a nested class that plainly exists in source, or 21 unrelated Run tests failing at once. It is not a code fault and no amount of reading the diff will find it: `:language:clean` (after `--stop`, since the daemon holds the jars) and rebuild. Interrupting a compile is the usual cause. Same shape as the harness note in memory, one layer down |
| **Refusing at the LOADER alone refuses mid-run, and a half-applied script is its own hazard** — `RefusedTypes` scans the compiled constant pool and refuses the whole script before a line of it executes | The two halves catch different things and neither is sufficient. The scan reads NAMES, so `Class.forName(built + "at" + "runtime")` puts only `java.lang.Class` in the pool and walks straight past it; the loader is the only place a late name is seen. But the loader only ever fires once the script is running, by which point it has done whatever it did before touching the class that stopped it. Both, or the control is either late or blind |
| **The JS resolution tiers live BESIDE the tree (child-side), not above the bridge** | `plan/lang-javascript.md` §3.1 put `JsResolver` host-side over a `JsAstView`; three of the four tiers read the tree (inference reads initializers, JSDoc reads the comment above a declaration, the declaration tier reads the scopes), so that shape is a bridge crossing per node walked, on every hover and every keystroke of a completion. The Java engine answers `resolveAt` on its own side and sends one `SymbolInfo` across — which is what the bridge is *for*: the answer crosses, never the tree |
| **The kill flag is the thread's own interrupt status, and a stop is an `Error`** | One `interrupt()` then reaches a *spinning* script through the injected check and a *blocked* one through `InterruptedException`; a private static would cover only the busy half. `Error` rather than `Exception` because scripts are full of `catch (Exception e)` around exactly the loop a stop must break out of. `catch (Throwable)` still defeats it and nothing cooperative can beat that — the trust model is the answer |
| **Semantic tokens REPLACE grammar tokens where they overlap; they do not layer** | Merged into one per-row bucket in `ensureRowSyntax`. Two overlapping ranges under unrelated names leave the winner to paint order, and **both names resolve to real colours** — so the wrong one reads as a scheme bug rather than an ordering one, which is exactly how the capture-precedence bug cost two rounds. Note the corollary when writing a test: a dotted capture is *also* published under its general form, so grammar-`variable` vs engine-`variable.parameter` cannot show the difference — assert on a pair where neither is the other's general form |
| A shipped third-party asset needs a notice file, not a javadoc comment | MIT requires its copyright notice to travel with the distribution and Apache 2.0 requires the licence, any NOTICE, and a statement of modifications. Naming the source in a class comment is good practice and satisfies neither. `THIRD-PARTY.md` indexes them |
| **A contextual keyword is a declaration only when a NAME follows it** | `class`, `interface` and `enum` are reserved, so seeing one is proof. `record` is not — `void f(Object record)` is ordinary Java, and `String.class` puts the keyword where no declaration is. Believed unconditionally, `SourceHeaders` treats the method's `{` as a type body, keeps it, and then scans its statements as if they were declarations: every `if (x) { … }` becomes `if (x) {}` and the output is neither the original nor a header. One token of lookahead is the actual grammar and disposes of both cases |
| **A child-side class may name only JDK types, `com.crystalgui.text.*` and the bridge — a shared utility is MOVED, never imported across** | The band loader is child-first over `com.crystalgui.language.*` and carries our own class files, so a child-side class importing `language.java` does not fail: it quietly defines a SECOND copy on the far side of the bridge, and two objects of "the same" type stop being assignable. `SimilarNames` was imported that way for a release — harmless, being stateless, and exactly the precedent not worth having. The rule is mechanical: **a class that imports `org.mozilla.javascript` is child-side**. It used to be a TABLE in `js/package-info.java`, because the `Js`/`Rhino` prefixes stopped saying which is which the moment the fix catalog turned out to need the AST — and a table is a thing that rots: it had `JsCompletionProvider` on the wrong side (it imports `java.TypeIndex` and `run.ScriptPolicy`, so it is host) and hedged on six classes with "loaded there in practice". It is now the **directory**: `js.host` and `js.rhino`, one rule each. The six hedged classes were settled by asking who calls them — every caller is child-side, so they are too |
| **The engine loader belongs on the thread for calls INTO the engine, and must come off for the script's own execution** | Rhino needs it up to `initStandardObjects`, which is where the regular-expression engine is resolved and cached. After that the script is calling OUT — into a mod's Java, into CrystalGUI — and leaving a child-first loader as the context loader makes every `ServiceLoader` in the application resolve against the engine's classpath, which is the same class of bug pointing the other way |
| **A completion fallback for "I cannot type this receiver" must fire on NO TYPE, never on an empty member list** | A receiver that resolved to `string` or `Array` and came back empty is a gap in `membersOf`, not an untypable receiver — so the popup offered every global the last run had left AS MEMBERS OF A STRING. The gap was real (the standard prototypes were never read; `getAllIds` is needed, since every prototype member is non-enumerable), and the fallback hid it: a list appeared, so nothing looked broken |

## Building, packaging and the loaders

| Invariant | Consequence if violated |
|---|---|
| **A CLASS THAT IS BOTH A MOD'S AND THE CLASSPATH'S IS TWO CLASSES, and only STATIC state makes it visible** | Fabric's Knot loads a mod jar's classes itself, so `com.crystalgraphics.platform.CgPlatform` inside CrystalGraphics' mod jar and on CrystalGUI's `runtimeClasspath` as `platform.jar` were two classes with a static registry each: CrystalGraphics registered into one and CrystalGUI read the other. The log printed *"Fabric 1.20.1 platform registered"* one second before the check printed *"CgPlatform not yet registered"* — which reads as an ordering bug and is an identity one. **A dependency that ships as a MOD must not also be on the consumer's runtime classpath**; forge and neoforge are unaffected only because theirs arrives as classpath jars rather than as a mod jar |
| **`LaunchClassLoader.getClassBytes` takes the UNTRANSFORMED name, and in dev the two spellings are identical** | So asking for `net.minecraft.world.World` returns the bytes in a dev client and **null** in production, where the jar entry is `ave.class` — every Minecraft type looks absent, and the namespace probe reports it cannot read `World` at all. `findClass` untransforms first, through an `IClassNameTransformer` that is private as a field and public as an ordinary entry in `getTransformers()`, so it is findable by type without reflection. The pair of names is then passed to each transformer rather than one name twice: a deobfuscating transformer decides what to rename from the difference between them |
| **Kotlin block comments NEST, unlike Java's** | A slash-star sequence inside a `.gradle.kts` doc comment — writing a glob like `META-INF/` followed by a literal star — opens a nested comment whose close ends only the inner one. Everything after it silently stops registering: `gradlew tasks` still succeeds, the build still passes, and the only symptom is a task that "does not exist". Cost an hour of looking at the wrong thing entirely |
| CrystalGraphics `platform` must stay on the headless classpath too — the excluded module is CG **core** | `Input` *implements* `CgSystemInput`; a supertype resolves at class load, so stripping it fails every input test with `NoClassDefFoundError` |

## Testing

| Invariant | Consequence if violated |
|---|---|
| **A fix's test asserts the TEXT the edit produces, never the edit's fields** | Applying the `ChangeSet` back to front and comparing the result is the only assertion that cannot pass against an edit at the wrong offsets — and back to front is what a `ChangeSet` means, since an earlier change must not move a later one's coordinates. A test that checked `from`/`to`/`insert` passes against a fix that lands one line up, which is exactly the failure mode of every offset-based rewrite |
| A `CompositeEdit` undoes in **reverse** | Each edit assumed the state the previous one left. The disconnect-then-connect pair is the smallest example: unwinding forwards restores an edge into an input that is still occupied |
| Truncation changes no geometry — `UIText.displayedText()` is the only way to observe it | An ellipsis that never fires looks identical to one that does, in every test and every layout dump |
| A closed `Dialog` is `display: none`, so every box in it measures 0 | Any "does it fit?" assertion passes against `0 <= 0` — call `show()` first |

## Everything else

| Invariant | Consequence if violated |
|---|---|
| **Two jars that split a Java PACKAGE must share a signing certificate** | Eclipse rotated its cert between 4.19 and 4.20, and `org.eclipse.core.runtime` is split across `core.runtime`, `equinox.common` and `equinox.registry`. Picking each artifact's newest Java-8-compatible version took jars from both sides, and a JVM refuses such a package with `SecurityException: signer information does not match` — after everything resolved, every class file was major 52 and the ceiling check went green. **Pinning is constrained by signing era as well as by bytecode version.** Two traps in checking it: `JarEntry.getCertificates()` answers null unless the entry is drained (and sometimes even then), and hashing only the *first* certificate compares the shared DigiCert intermediate rather than the leaf — which made the check pass on the exact pin it was written to catch |
| **A denylist is unsound and is still the right shape for a GUARDRAIL** | The rule was allowlist-only, because a denylist is wrong the moment a new class appears. Still true, and still why a denylist may never carry a security claim — but the allowlist a usable guardrail needs is the host API plus the MC surface plus a slice of `java.*`, which is thousands of entries. **A control nobody will write is worse than a leaky one that gets used.** So they compose rather than replace: a denial is a **veto**, asked before the allowlist, or an `allow java.lang` would re-permit a `deny java.lang.reflect` and `UNSAFE` would mean whatever the two lists happened to say about each other |
| **A cooperative safepoint must be injected as a CALL, never as a read-and-branch** | A new branch target in a Java 7+ class file needs a new `StackMapTable` entry → `COMPUTE_FRAMES` → ASM calling `getCommonSuperClass` → **loading classes at instrumentation time**, which on a Minecraft host means loading MC classes while compiling and fails outright for a type not yet loadable. A single `invokestatic` of a void no-arg method adds no branch, no local and no stack depth, so every frame and max stays valid — and HotSpot inlines the callee back to the volatile read the obvious version would have emitted |
| **A modifier overlay is a FULL-SIZE layer, not a badge in a corner box** | JetBrains draws `staticMark`/`finalMark` on their own 16×16 canvases with the glyph already placed — static bottom-left, final top-left — so they compose by stacking at the icon's size and both can show at once. Scaled into a small corner instead, a mark silently draws a third too large and in the wrong corner, which reads as bad artwork. **They must carry the icon's size**, not the artwork's |
| **A hint strip must be DERIVED from the key table its handler reads** | "Press Enter to insert, Tab to replace" written as a literal is a promise that stops being kept the first time a binding moves, with nothing failing when it does. And it was already untrue — both keys merely accepted — so making the strip honest meant implementing replace. A strip is not decoration: the two keys differ and nothing else says so |
| Only `AnchoredPlacement` writes `left`/`top` on an anchored popup | Any other writer fights placement every frame |
| Selection is **not** undoable | The majority choice and a live disagreement — Blender records it and is criticised for being "counter to basically all other applications"; Figma has a standing request for it as a preference. Ours is VS Code's: selection is view state, and an *edit*'s undo restores the selection that edit applied to |
| An input port takes **one** edge, an output **many** — so connecting to an occupied input *replaces* | Refusing it looks like correct validation and makes rewiring take two gestures. The displaced edge must leave through the same `disconnect` as a manual one, or 6.2.4's undo will not know it happened |
| The canvas culls with `opacity: 0`, **not** `display: none` | A culled node's layout rect is the input its own cull decision is computed from. Collapse it and the node can never be un-culled without a cache of where it used to be — which then goes stale whenever anything moves it. Keeping layout live is what makes the decision self-correcting |
| An icon's colour comes from the `.filetype-*` class, never from the theme JSON | A dozen languages share one `code` glyph and still need their own colours — keying colour to the icon cannot express that. Same split `graph.css` already makes for port types |
| `inert` keeps its box — it is not a spelling of `display: none` | The one reason both exist; if inert ever stops laying out, it has become a worse `display: none` |
| Exactly one tab in a `TabView` strip is tabbable, falling back to the first when nothing is selected | Zero tab stops — the whole tablist disappears from the keyboard |
| A pooled gutter arrow's row is read **per frame**, never captured in its listener | Arrows recycle as the view scrolls, and a listener may only be attached once. Capture the row and the arrow keeps toggling whatever row its slot was first used for — which keeps working for exactly as long as nobody scrolls |
| **An operator predicate written as "ends with `=` and does not begin with one" excludes plain `=`** | Which is the case that matters. `xs[i] = 0` was therefore read as a FETCH, so the index loop converted to `for…of` and the body became `x = 0` — assigning to the loop variable and discarding it. The array stops being written, nothing throws, and the diff looks like the refactoring it was advertised as. List the assignment operators; there are sixteen and they are not going to change |
| **A `transform` list applies its RIGHTMOST function first, and a single function cannot tell you which way you read it** | `SvgTransform.parse` composed left to right for as long as it existed and every shipped icon carries at most one function, so nothing could disagree. The idiom that can is scaling about a point — `translate(36 32) scale(0.42) translate(-32 -32)`, which is what Illustrator and Inkscape write for every nested group — and read the wrong way it put the logo's gem at `(-3, -5)`: off the canvas, no error, an icon that simply lacked a part. `SvgTransformOrderTest` pins the spec's own equivalence (`translate(10,20) scale(2)` **is** `matrix(2 0 0 2 10 20)`); the tree composition in `SvgResolver` was always right, which is why one level of `<g transform>` worked and a chain did not |
| **An arc's segment count is per QUARTER TURN, never per command** | `SvgPath.arc` gave every arc the same `steps` whatever its sweep, so at the 8-step tile tier a rounded corner and a whole circle were both eight segments — the corner smooth, the circle an octagon, and a 296° letterform a rough polygon beside perfectly round tile corners. Invisible in the shipped set because Feather rounds corners with quarter arcs and nothing drew a large one small. Normalised on the quarter with `round` rather than `ceil`, so a corner is byte-for-byte what it was and float error cannot add a segment |
